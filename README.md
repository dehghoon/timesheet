# Timesheet MVP

یک تایم‌شیت کوچک برای تیم حدوداً ۱۰ نفره، با ثبت‌نام و ورود نام کاربری/رمز عبور، ثبت تاریخ و ساعت شروع/پایان، شرح کار، دسترسی مدیر و خروجی CSV.

## امکانات

- ثبت‌نام کاربر با نام کاربری و رمز عبور
- ورود با نام کاربری و رمز عبور
- هر عضو فقط رکوردهای خودش را می‌بیند
- مدیر همه رکوردها را می‌بیند
- محاسبه خودکار مدت کار
- خروجی CSV برای اتصال بعدی به سیستم مالی
- رابط فارسی و واکنش‌گرا
- دیتابیس و احراز هویت با Supabase

## راه‌اندازی

1. در Supabase یک پروژه رایگان بسازید.
2. محتوای `supabase.sql` را در SQL Editor اجرا کنید.
3. در Authentication > Providers، ورود Email/Password را فعال کنید.
4. چون اپ برای نام کاربری‌های داخلی از آدرس‌های مصنوعی مثل `sara@timesheet.local` استفاده می‌کند، گزینه Confirm email را خاموش کنید تا کاربر بلافاصله بعد از ثبت‌نام بتواند وارد شود.
5. در `index.html` مقادیر `YOUR_SUPABASE_URL` و `YOUR_SUPABASE_ANON_KEY` را جایگزین کنید. کلید anon برای فرانت‌اند طراحی شده و امنیت داده‌ها با RLS داخل `supabase.sql` اعمال می‌شود.
6. برای مدیر کردن یک کاربر، این دستور را در SQL Editor اجرا کنید:

```sql
update public.profiles set role = 'admin' where username = 'your_admin_username';
```

7. اپ را روی Vercel منتشر کنید. Repository را متصل کنید، Branch را روی `agent/timesheet-mvp` برای Preview یا روی `main` بعد از Merge قرار دهید، و Framework Preset را روی `Other` بگذارید. Build Command لازم نیست و Output Directory همان ریشه پروژه است.

## ثبت‌نام

کاربر از تب «ثبت‌نام» یک نام کاربری و رمز عبور حداقل ۸ کاراکتری انتخاب می‌کند. نام کاربری فقط می‌تواند شامل حروف انگلیسی، عدد، نقطه، خط تیره و زیرخط باشد. حساب به‌صورت خودکار در Supabase Auth ساخته می‌شود و Trigger موجود در `supabase.sql` پروفایل متناظر را با نقش پیش‌فرض `member` ایجاد می‌کند.

## اتصال بعدی به Wave

در نسخه فعلی خروجی CSV فراهم شده تا گزارش ساعت‌ها قابل انتقال و پردازش باشد. مرحله بعد می‌تواند یک سرویس سمت سرور برای تبدیل گزارش‌های تأییدشده به داده‌های مالی یا فاکتور باشد؛ کلیدها و توکن‌های Wave نباید در `index.html` قرار بگیرند.

## نکته امنیتی

این اپ برای استفاده داخلی طراحی شده است. رمزها در Supabase Auth نگهداری می‌شوند و در دیتابیس اپ ذخیره نمی‌شوند. سیاست‌های Row Level Security دسترسی اعضا و مدیر را محدود می‌کنند. ثبت‌نام عمومی باز است؛ اگر فقط اعضای دعوت‌شده باید حساب بسازند، در نسخه بعدی باید invite code یا allowlist اضافه شود.
